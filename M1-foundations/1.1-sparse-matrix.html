M1.1 · FOUNDATIONS

計數矩陣與稀疏儲存

Count Matrices & Sparse Storage

95% 是零的矩陣，怎麼放進記憶體？CSR / CSC / COO 三種編碼的本質差異。

When a matrix is 95% zero, how do we store it? Essential differences between CSR, CSC, COO encodings.

直覺 / Intuition

為什麼 scRNA-seq 矩陣會這麼稀疏？

Why are scRNA-seq matrices so sparse?

一個典型 10x Genomics 實驗：10,000 細胞 × 20,000 基因 = 2 億個元素。 但每個細胞實際上「捕捉到」的 mRNA 分子數通常只有 1,000~5,000 種基因。 所以這個矩陣裡大約 90-95% 的元素是 0。

用普通 numpy.ndarray（dense）儲存： $200,000,000 \times 8 \text{ bytes} = 1.6 \text{ GB}$——光是讀進來就吃光記憶體。

核心問題：有 95% 是 0 的資料，為什麼要花空間記錄那些 0？

A typical 10x Genomics experiment: 10,000 cells × 20,000 genes = 200 million entries. But each cell actually captures only ~1,000–5,000 detectable genes worth of mRNA. So about 90–95% of the matrix is zero.

Storing with plain numpy.ndarray (dense): $200{,}000{,}000 \times 8 \text{ bytes} = 1.6 \text{ GB}$ — just loading exhausts memory.

The core question: why store all those zeros explicitly?

核心數學 / Math

三種稀疏編碼：COO · CSR · CSC

Three Sparse Encodings: COO · CSR · CSC

COO (Coordinate format)

最直觀：用三個平行陣列記錄「行、列、值」。

Most intuitive: three parallel arrays storing row, col, value.

$$\text{COO}(A) = \{(i_k, j_k, v_k) : v_k \neq 0\}_{k=1}^{\text{nnz}}$$
nnz = number of non-zeros（非零元素數）。需要 3 個長度為 nnz 的陣列。
nnz = number of non-zeros. Requires 3 arrays of length nnz.

記憶體：$\text{nnz} \times (4 + 4 + 8) = 16 \text{ bytes per nnz}$（int32 + int32 + float64）

Memory: $\text{nnz} \times (4 + 4 + 8) = 16 \text{ bytes per nnz}$ (int32 + int32 + float64)

CSR (Compressed Sparse Row)

把 COO 的「行索引」進一步壓縮成「每列從哪一個位置開始」的指標。

Compresses COO's row indices into pointers indicating where each row starts.

$$\text{CSR}(A) = \begin{cases} \text{values}[k] = v_k & k = 1, \dots, \text{nnz} \\ \text{col\_idx}[k] = j_k & k = 1, \dots, \text{nnz} \\ \text{row\_ptr}[i] = \text{第 } i \text{ 列第一個非零在 values 的索引} & i = 0, \dots, n \end{cases}$$

第 $i$ 列的非零元素 = values[row_ptr[i] : row_ptr[i+1]]。 記憶體：$\text{nnz} \times 12 + (n+1) \times 4$ bytes。列向操作（row-slicing、SpMV）特快。

Row $i$'s non-zeros are values[row_ptr[i] : row_ptr[i+1]]. Memory: $\text{nnz} \times 12 + (n+1) \times 4$ bytes. Row-slicing and SpMV are very fast.

CSC (Compressed Sparse Column)

CSR 的轉置版本：壓縮列索引，得到「每行從哪開始」的指標。行向操作快（例如「取出基因 $g$ 在所有細胞的表現」）。

Transpose of CSR: compresses column indices into column pointers. Column-slicing is fast (e.g., "expression of gene $g$ across all cells").

💡 何時用 CSR vs CSC？ 💡 When to use CSR vs CSC?

Scanpy 用 CSR（細胞為列，QC、subset cells 很多）。
Seurat 內部用 dgCMatrix = CSC（基因為列，DE、HVG 是 per-gene 操作）。

Scanpy uses CSR (cells as rows, frequent cell subsetting).
Seurat uses dgCMatrix = CSC internally (genes as columns, DE/HVG are per-gene).

演算法 / Algorithm

稀疏矩陣乘以密集向量 (SpMV)

Sparse Matrix × Dense Vector (SpMV)

PCA、KNN graph 都需要 $\mathbf{A} \mathbf{x}$ 運算（$\mathbf{A}$ 稀疏、$\mathbf{x}$ 密集）。CSR 形式下：

PCA, KNN graph all need $\mathbf{A} \mathbf{x}$ (sparse $\mathbf{A}$, dense $\mathbf{x}$). In CSR:

# Input: A (CSR with values, col_idx, row_ptr), x (dense vector) # Output: y = A @ x for i in range(n): y[i] = 0 for k in range(row_ptr[i], row_ptr[i+1]): j = col_idx[k] y[i] += values[k] * x[j] # 只算非零項

複雜度：$O(\text{nnz})$，而非 dense 的 $O(nm)$。 10,000 × 20,000、5% 密度 → CSR SpMV 比 dense 快 ~20 倍。

Complexity: $O(\text{nnz})$ instead of dense $O(nm)$. 10,000 × 20,000 at 5% density → CSR SpMV is ~20× faster than dense.

程式碼 / Code

實作範例

Code Examples

import scanpy as sc
import scipy.sparse as sp

# 載入時就是 CSR 格式
adata = sc.read_h5ad("pbmc.h5ad")
print(type(adata.X))    # scipy.sparse._csr.csr_matrix
print(adata.X.nnz)      # 非零元素總數
print(adata.X.shape)    # (n_cells, n_genes)

# 密度
density = adata.X.nnz / (adata.X.shape[0] * adata.X.shape[1])
print(f"Density: {density:.2%}")

# 取一列 = 一個細胞（CSR 適合）
cell_row = adata.X[0]                 # O(平均 nnz/n)

# 取一行 = 一個基因（CSC 適合，CSR 慢）
adata.X_csc = adata.X.tocsc()
gene_col = adata.X_csc[:, gene_idx]   # O(平均 nnz/m)

library(Matrix)
library(Seurat)

# Seurat 內部使用 dgCMatrix = CSC 格式
pbmc <- Read10X("data/")
class(pbmc)              # "dgCMatrix"
dim(pbmc)                # [基因數, 細胞數]

# 取出非零項數量
nnz <- length(pbmc@x)
density <- nnz / prod(dim(pbmc))
cat(sprintf("Density: %.2f%%\n", density*100))

# dgCMatrix 三個 slot 對應 CSC 編碼
pbmc@x       # values
pbmc@i       # row indices (對應 col_idx 的角色)
pbmc@p       # column pointers

# 行操作（取基因）快
gene_expr <- pbmc["CD3D", ]    # O(該基因的 nnz)

Integration：把多個 batch 整合在一起

Integration: combining multiple batches

你有兩份 10x 資料：lab A 的 5,000 個細胞、lab B 的 8,000 個。 生物上它們是同樣的組織型態（都是 PBMC），但跑 PCA + UMAP 你會看到細胞按 batch 分開， 而不是按細胞型態分開——技術變異把生物訊號蓋掉了。

本節從這個 batch effect 的具體現象出發，介紹三種主流校正方法： Harmony（PC 空間迭代軟分群校正）、 BBKNN（跨 batch KNN 圖修補）、 scVI（變分自動編碼器 + batch covariate）。 最後談 kBET / LISI 等評估指標跟過度校正的風險。
You have two 10x datasets: lab A's 5,000 cells, lab B's 8,000. Biologically they're the same tissue (both PBMC), but PCA + UMAP shows cells splitting by batch, not by cell type — technical variation has masked the biological signal.

Starting from concrete batch effect phenomena, we cover three mainstream methods: Harmony (PC-space iterative soft-cluster correction), BBKNN (cross-batch KNN graph patching), scVI (variational autoencoder + batch covariate). Finally kBET / LISI evaluation metrics and over-correction risks.

§0 故事：UMAP 為什麼按 batch 分？Story: why does UMAP split by batch?

Lab A 用 10x v3 跑 5,000 PBMC、Lab B 用 10x v2 跑 8,000 PBMC。兩邊都有 T cell、B cell、monocytes。 合併矩陣、做 PCA、UMAP。 理想：UMAP 上 T cell 都聚一起、B cell 都聚一起、monocyte 都聚一起。 實際：Lab A 的 T cell + Lab A 的 B cell 一團，Lab B 的 T cell + Lab B 的 B cell 另一團——按 batch 分。

Lab A: 5,000 PBMC with 10x v3. Lab B: 8,000 PBMC with 10x v2. Both have T cells, B cells, monocytes. Combine matrices, PCA, UMAP. Ideal: T cells together, B cells together, monocytes together. Reality: Lab A's T + B in one blob, Lab B's T + B in another — splits by batch.

§2 Harmony 的迭代校正數學Harmony iterative math

Harmony（Korsunsky et al. 2019）在 PC 空間校正（不動原始 count matrix）。三步驟反覆迭代：

Harmony (Korsunsky et al. 2019) operates in PC space (doesn't modify raw counts). Iterates 3 steps:

2.1 三步驟

2.1 Three steps

  1. 軟分群：對 PC embedding 做 fuzzy k-means，每細胞 $i$ 得 cluster 機率 $R_{ik}$。 Soft clustering: fuzzy k-means on PCs, cell $i$ gets cluster probabilities $R_{ik}$.
  2. 計算校正：每 cluster 算「各 batch 的中心位置」，計算把每 batch 拉回 cluster centroid 需要的位移向量。 Compute correction: per cluster, find each batch's centroid, compute displacement vector to pull each batch back to cluster centroid.
  3. 更新 embedding：每細胞按其 $R_{ik}$ 加權套用位移，得到校正後 PCA。 Update embedding: each cell applies displacements weighted by $R_{ik}$, gets corrected PCs.
$$\hat{Z}_i = Z_i - \sum_k R_{ik} \sum_b \frac{n_{kb}}{n_k} (\mu_{kb} - \mu_k)$$
$Z_i$ = 細胞 $i$ 的 PC、$\mu_{kb}$ = cluster $k$ batch $b$ 中心、$\mu_k$ = cluster 中心、$n_{kb}$ = 該 cluster 該 batch 細胞數
$Z_i$ = cell $i$'s PCs, $\mu_{kb}$ = cluster $k$ batch $b$ centroid, $\mu_k$ = cluster centroid

2.2 為什麼有效？

2.2 Why does it work?

校正向量大小由「不同 batch 偏離 cluster 中心多遠」決定。若某 cluster 在 batch A、B 中心一樣 → 零位移。 若 batch A 在 cluster 中心右邊、batch B 在左邊 → 把 A 推左、B 推右，讓兩 batch 合在中心。 迭代直到偏移 < ε（通常 10 次以內收斂）。

Correction magnitude depends on how far each batch deviates from cluster centroid. If batch A and B centroids coincide → zero shift. If A is right of centroid, B is left → push A left, B right, merging both at centroid. Iterate until shifts < ε (typically converges in < 10 iters).

§4 BBKNN：跨 batch 鄰居修補BBKNN: cross-batch neighbor patching

BBKNN（Polański et al. 2020）不改變 PC 座標，改的是 KNN graph： 對每個細胞 $i$，限制它在 每個 batch 中各找 k 個鄰居，而非全域 k 個。

BBKNN (Polański et al. 2020) doesn't change PCs — it modifies the KNN graph: for each cell $i$, find k neighbors in each batch separately, not globally.

4.1 為什麼簡單但有效

4.1 Why simple yet effective

直覺Intuition: 如果你強迫每細胞至少有 k 個鄰居來自每個 batch，那 KNN 圖會必然連通兩 batch。 下游 Leiden / UMAP 看到的是合在一起的圖。對 batch effect 小但不為零的情境特別有效。 If you force each cell to have k neighbors from every batch, the KNN graph must connect across batches. Downstream Leiden / UMAP sees a unified graph. Especially effective when batch effects are small but non-zero. 
import bbknn

bbknn.bbknn(adata, batch_key="sample", neighbors_within_batch=3, n_pcs=30)

§5 scVI：變分自動編碼器scVI: variational autoencoder

scVI（Lopez et al. 2018）用深度生成模型。把每細胞 count 編碼成 latent vector $\mathbf{z}_i$，再 decode 回 NB 參數。 關鍵：encoder 跟 decoder 都條件在 batch label $s_i$ 上。

scVI (Lopez et al. 2018) uses a deep generative model. Each cell's counts encoded to latent $\mathbf{z}_i$, decoded back to NB params. Key: both encoder and decoder condition on batch label $s_i$.

$$\mathbf{z}_i = f_\text{enc}(\mathbf{x}_i, s_i), \quad \mathbf{x}_i \sim \text{NB}(f_\text{dec}(\mathbf{z}_i, s_i), \theta)$$
latent space $\mathbf{z}_i$ 不含 batch 資訊（被條件移除）
latent $\mathbf{z}_i$ is batch-free (removed via conditioning)

訓練後，所有細胞在同一個 latent space 比較，下游用 $\mathbf{z}$ 取代 PCA。

After training, all cells share one latent space; downstream uses $\mathbf{z}$ instead of PCA.

5.1 scVI 的優勢

5.1 scVI's advantages

  • 處理非線性 batch effect（Harmony 是線性）
  • handles nonlinear batch effects (Harmony is linear)
  • 直接在 count level 工作（不需 PCA 預處理）
  • works at count level (no PCA preprocessing needed)
  • 擴展性：100 萬細胞可行
  • scales: 1M cells feasible
  • 延伸 scANVI 可半監督
  • scANVI extension is semi-supervised

§7 評估指標：kBET / LISIMetrics: kBET / LISI

校正後怎麼知道夠好？兩個常用指標：

How to know correction is good enough? Two common metrics:

7.1 kBET (k-nearest neighbor Batch Effect Test)

7.1 kBET

$$\text{kBET}_i: \chi^2 \text{ test on whether } \mathcal{N}_k(i) \text{ has expected batch composition}$$

對每細胞檢驗其 k 個鄰居的 batch 分布是否符合整體 batch 比例。理想：每細胞鄰居中 batch 比例 ≈ 全域比例 → kBET 通過率高。

Per-cell test: are the k neighbors' batches distributed like the overall batch proportions? Ideal: yes → high kBET pass rate.

7.2 LISI (Local Inverse Simpson Index)

7.2 LISI

$$\text{iLISI}_i = \frac{1}{\sum_b p_{ib}^2}, \quad p_{ib} = \frac{|\mathcal{N}_k(i) \cap \text{batch } b|}{k}$$

iLISI（integration LISI）越接近 batch 數越好（鄰居完全混合）。 cLISI（cell-type LISI）越接近 1 越好（鄰居都是同型態）。理想：iLISI 高、cLISI 低。

iLISI (integration LISI) → batch count = perfectly mixed. cLISI (cell-type LISI) → 1 = neighbors are same type. Ideal: high iLISI, low cLISI.

過度校正的訊號Over-correction signal: cLISI 上升（不同型態混在一起）就是過度校正——把生物差異也磨掉了。 cLISI rising (different types mix together) = over-correction — biological differences erased.

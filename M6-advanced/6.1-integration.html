Integration：把多個 batch 整合在一起

Integration: combining multiple batches

你有兩份 10x 資料：lab A 的 5,000 個細胞、lab B 的 8,000 個。 生物上它們是同樣的組織型態（都是 PBMC），但跑 PCA + UMAP 你會看到細胞按 batch 分開， 而不是按細胞型態分開——技術變異把生物訊號蓋掉了。

本節從這個 batch effect 的具體現象出發，介紹三種主流校正方法： Harmony（PC 空間迭代軟分群校正）、 BBKNN（跨 batch KNN 圖修補）、 scVI（變分自動編碼器 + batch covariate）。 最後談 kBET / LISI 等評估指標跟過度校正的風險。
You have two 10x datasets: lab A's 5,000 cells, lab B's 8,000. Biologically they're the same tissue (both PBMC), but PCA + UMAP shows cells splitting by batch, not by cell type — technical variation has masked the biological signal.

Starting from concrete batch effect phenomena, we cover three mainstream methods: Harmony (PC-space iterative soft-cluster correction), BBKNN (cross-batch KNN graph patching), scVI (variational autoencoder + batch covariate). Finally kBET / LISI evaluation metrics and over-correction risks.

🧬 scRNA-seq 視角：Integration 是把不同樂團「調到同一個音準」 🧬 scRNA-seq perspective: Integration tunes different orchestras to the same pitch

想像紐約愛樂、東京交響、柏林愛樂三個樂團要合奏同一首貝多芬第九。問題：紐約樂團校準到 A=440Hz、東京到 442Hz、柏林到 443Hz——同一個音 La 三個樂團聽起來都不一樣。如果你不先調音就讓他們一起拉，聽眾會以為「紐約小提琴跟柏林小提琴是不同樂器」。scRNA 多 sample 的 batch effect 就是這件事：lab A 用 10x v2、lab B 用 v3、lab C 換了 reagent 批號——三邊的 PBMC本來是同樣的細胞，但 PCA 跑出來會按 lab 分群，不是按 cell type。 Imagine the NY Philharmonic, Tokyo Symphony, and Berlin Philharmonic jointly performing Beethoven's 9th. Problem: NY tunes to A=440Hz, Tokyo to 442Hz, Berlin to 443Hz — the same note A sounds different in each orchestra. Without tuning first, the audience thinks "NY violins and Berlin violins are different instruments". scRNA's multi-sample batch effect is exactly this: lab A uses 10x v2, lab B uses v3, lab C changed reagent batches — the PBMCs are biologically the same cells, but PCA groups them by lab, not cell type.

Integration 就是「統一調音」。Harmony 一邊一邊地把每個 batch 的細胞拉到「跨 batch 的中心」，scVI 用 deep learning 把 batch 當「干擾因子」減掉。但小心過度校正：你不能把「不同樂團演奏速度」（真實的疾病差異）也校掉，否則「紐約是 disease group、柏林是 healthy」這個你要找的差異也被一起抹平了。所以 integration 是場走鋼索的遊戲——kBET 量「batch 是否混好」、cell-type ARI 量「細胞型是否保持原樣」，兩個分數要同時高才算成功。 Integration is "unified tuning". Harmony iteratively pulls each batch's cells toward the "cross-batch center"; scVI uses deep learning to subtract batch as a confounder. But beware over-correction: you can't tune away "different tempo between orchestras" (real disease differences), or else the "NY is disease, Berlin is healthy" signal you want to find also gets erased. So integration is a tightrope walk — kBET measures "are batches mixed", cell-type ARI measures "are cell types preserved"; both must score high for success.

📍 在 scRNA-seq 流程中的位置Position in scRNA-seq pipeline

QC → normalize → HVG → PCA → Integration (Harmony / BBKNN / scVI) → corrected PCA / embedding → KNN → Leiden → UMAP → DE / annotation

當你有多個 sample（不同 patient、不同 lab、不同 10x version、不同 time point）時，「batch effect」會把生物訊號蓋掉。Integration 就是把技術變異拆掉、留生物變異的步驟。沒它，後面所有跨 sample 的比較（healthy vs disease、treatment vs control）都不可信。 When you have multiple samples (different patients, labs, 10x versions, time points), batch effects mask biological signal. Integration is the step that removes technical variation while preserving biological variation. Without it, all cross-sample comparisons (healthy vs disease, treatment vs control) become unreliable.

🎯 為什麼 scRNA-seq 跨樣本研究必須做 integrationWhy scRNA-seq cross-sample studies must do integration

  • batch effect 在 scRNA 比 bulk 嚴重百倍Batch effect in scRNA is 100× worse than bulk： 不同 10x kit version（v2 vs v3）、不同 sequencing depth、不同 sample prep 操作員，產生的 capture efficiency 跟 dropout pattern 差很多。同 patient 同 tissue 用兩個 batch 跑出來都會分群——Tran 2020 比較 14 種 integration 工具就是因為這事太嚴重。 Different 10x kit versions (v2 vs v3), depths, prep operators produce very different capture efficiencies and dropout patterns. Same patient + same tissue + 2 batches will split — Tran 2020's benchmark of 14 integration tools exists because this problem is severe.
  • 疾病 vs control 的核心問題Core question of disease vs control： paper 標題「COVID-19 患者的 T cell 表現差異」必然需要 integrate 多個 patient sample；如果 batch effect 還在，DE 找到的 gene 是「sample-specific noise」而非 disease signal。 Paper titles like "T cell differences in COVID-19 patients" necessarily require integrating multiple patient samples; if batch effects remain, DE genes are "sample-specific noise", not disease signal.
  • atlas 建構的基礎Foundation for atlas construction： HCA、CELLxGENE、Tabula Sapiens 等大規模 atlas 整合來自數十到數百個 lab 的資料，沒 Harmony / scVI 級別的 integration，atlas 變成「按 lab 分群」沒生物意義。 HCA, CELLxGENE, Tabula Sapiens etc. aggregate data from tens to hundreds of labs; without Harmony / scVI-level integration, atlas becomes "lab-grouped" with no biological meaning.

§2 Harmony 的迭代校正數學Harmony iterative math

Harmony（Korsunsky et al. 2019）在 PC 空間校正（不動原始 count matrix）。三步驟反覆迭代：

Harmony (Korsunsky et al. 2019) operates in PC space (doesn't modify raw counts). Iterates 3 steps:

2.1 三步驟

2.1 Three steps

  1. 軟分群：對 PC embedding 做 fuzzy k-means，每細胞 $i$ 得 cluster 機率 $R_{ik}$。 Soft clustering: fuzzy k-means on PCs, cell $i$ gets cluster probabilities $R_{ik}$.
  2. 計算校正：每 cluster 算「各 batch 的中心位置」，計算把每 batch 拉回 cluster centroid 需要的位移向量。 Compute correction: per cluster, find each batch's centroid, compute displacement vector to pull each batch back to cluster centroid.
  3. 更新 embedding：每細胞按其 $R_{ik}$ 加權套用位移，得到校正後 PCA。 Update embedding: each cell applies displacements weighted by $R_{ik}$, gets corrected PCs.
$$\hat{Z}_i = Z_i - \sum_k R_{ik} \sum_b \frac{n_{kb}}{n_k} (\mu_{kb} - \mu_k)$$
$Z_i$ = 細胞 $i$ 的 PC、$\mu_{kb}$ = cluster $k$ batch $b$ 中心、$\mu_k$ = cluster 中心、$n_{kb}$ = 該 cluster 該 batch 細胞數
$Z_i$ = cell $i$'s PCs, $\mu_{kb}$ = cluster $k$ batch $b$ centroid, $\mu_k$ = cluster centroid

2.2 為什麼有效？

2.2 Why does it work?

校正向量大小由「不同 batch 偏離 cluster 中心多遠」決定。若某 cluster 在 batch A、B 中心一樣 → 零位移。 若 batch A 在 cluster 中心右邊、batch B 在左邊 → 把 A 推左、B 推右，讓兩 batch 合在中心。 迭代直到偏移 < ε（通常 10 次以內收斂）。

Correction magnitude depends on how far each batch deviates from cluster centroid. If batch A and B centroids coincide → zero shift. If A is right of centroid, B is left → push A left, B right, merging both at centroid. Iterate until shifts < ε (typically converges in < 10 iters).

§4 BBKNN：跨 batch 鄰居修補BBKNN: cross-batch neighbor patching

BBKNN（Polański et al. 2020）不改變 PC 座標，改的是 KNN graph： 對每個細胞 $i$，限制它在 每個 batch 中各找 k 個鄰居，而非全域 k 個。

BBKNN (Polański et al. 2020) doesn't change PCs — it modifies the KNN graph: for each cell $i$, find k neighbors in each batch separately, not globally.

4.1 為什麼簡單但有效

4.1 Why simple yet effective

直覺Intuition: 如果你強迫每細胞至少有 k 個鄰居來自每個 batch，那 KNN 圖會必然連通兩 batch。 下游 Leiden / UMAP 看到的是合在一起的圖。對 batch effect 小但不為零的情境特別有效。 If you force each cell to have k neighbors from every batch, the KNN graph must connect across batches. Downstream Leiden / UMAP sees a unified graph. Especially effective when batch effects are small but non-zero.

§5 scVI：變分自動編碼器scVI: variational autoencoder

scVI（Lopez et al. 2018）用深度生成模型。把每細胞 count 編碼成 latent vector $\mathbf{z}_i$，再 decode 回 NB 參數。 關鍵：encoder 跟 decoder 都條件在 batch label $s_i$ 上。

scVI (Lopez et al. 2018) uses a deep generative model. Each cell's counts encoded to latent $\mathbf{z}_i$, decoded back to NB params. Key: both encoder and decoder condition on batch label $s_i$.

$$\mathbf{z}_i = f_\text{enc}(\mathbf{x}_i, s_i), \quad \mathbf{x}_i \sim \text{NB}(f_\text{dec}(\mathbf{z}_i, s_i), \theta)$$
latent space $\mathbf{z}_i$ 不含 batch 資訊（被條件移除）
latent $\mathbf{z}_i$ is batch-free (removed via conditioning)

訓練後，所有細胞在同一個 latent space 比較，下游用 $\mathbf{z}$ 取代 PCA。

After training, all cells share one latent space; downstream uses $\mathbf{z}$ instead of PCA.

5.1 scVI 的優勢

5.1 scVI's advantages

  • 處理非線性 batch effect（Harmony 是線性）
  • handles nonlinear batch effects (Harmony is linear)
  • 直接在 count level 工作（不需 PCA 預處理）
  • works at count level (no PCA preprocessing needed)
  • 擴展性：100 萬細胞可行
  • scales: 1M cells feasible
  • 延伸 scANVI 可半監督
  • scANVI extension is semi-supervised

§7 評估指標：kBET / LISIMetrics: kBET / LISI

校正後怎麼知道夠好？兩個常用指標：

How to know correction is good enough? Two common metrics:

7.1 kBET (k-nearest neighbor Batch Effect Test)

7.1 kBET

$$\text{kBET}_i: \chi^2 \text{ test on whether } \mathcal{N}_k(i) \text{ has expected batch composition}$$

對每細胞檢驗其 k 個鄰居的 batch 分布是否符合整體 batch 比例。理想：每細胞鄰居中 batch 比例 ≈ 全域比例 → kBET 通過率高。

Per-cell test: are the k neighbors' batches distributed like the overall batch proportions? Ideal: yes → high kBET pass rate.

7.2 LISI (Local Inverse Simpson Index)

7.2 LISI

$$\text{iLISI}_i = \frac{1}{\sum_b p_{ib}^2}, \quad p_{ib} = \frac{|\mathcal{N}_k(i) \cap \text{batch } b|}{k}$$

iLISI（integration LISI）越接近 batch 數越好（鄰居完全混合）。 cLISI（cell-type LISI）越接近 1 越好（鄰居都是同型態）。理想：iLISI 高、cLISI 低。

iLISI (integration LISI) → batch count = perfectly mixed. cLISI (cell-type LISI) → 1 = neighbors are same type. Ideal: high iLISI, low cLISI.

過度校正的訊號Over-correction signal: cLISI 上升（不同型態混在一起）就是過度校正——把生物差異也磨掉了。 cLISI rising (different types mix together) = over-correction — biological differences erased.

9.2 評估指標：14 個 metrics 的整合

Luecken 用加權 scoring：60% batch correction metrics (NMI, ARI, F1 of LISI) + 40% biology conservation (ASW per cell type, isolated label F1, etc.)。「好的 integration」= batch 混合 + 生物保留。

§10 深入：scVI ELBO 推導Deep dive: scVI ELBO derivation

scVI is a VAE trained with ELBO. Full formula and scRNA interpretation.

10.1 ELBO 完整公式

10.1 ELBO formula

$$\mathcal{L}_{\text{scVI}} = \mathbb{E}_{q_\phi(z, l|x)}\!\left[\log p_\theta(x|z, l, s)\right] - \text{KL}\!\left[q_\phi(z|x) \| p(z)\right] - \text{KL}\!\left[q_\phi(l|x) \| p(l|s)\right]$$

三部分解讀：

Three parts:

  • Reconstruction: $\log p_\theta(x|z, l, s)$ — counts 用 NB likelihood。學「給 z, l, batch s, 怎麼產生原始 counts」
  • Reconstruction: $\log p_\theta(x|z, l, s)$ — counts use NB likelihood. Learn "given z, l, batch s, how to generate raw counts"
  • z prior KL: 強制 z 接近 N(0, I)，避免 overfitting
  • z prior KL: forces z toward N(0, I), prevents overfitting
  • l prior KL: library size scaling，跟 batch 條件相關
  • l prior KL: library size scaling, batch-conditioned

10.2 為什麼這設計能消 batch

10.2 Why this removes batch

關鍵Key: encoder $q_\phi(z|x)$ 不條件在 $s$ 上——z 必須能跨 batch 重建 x。decoder $p_\theta(x|z, s)$ 條件在 $s$——batch 訊息只能透過 decoder 加回去。所以 z 必然是 batch-free。 Encoder $q_\phi(z|x)$ not conditioned on $s$ — z must reconstruct x across batches. Decoder $p_\theta(x|z, s)$ is conditioned on $s$ — batch info enters only via decoder. So z is necessarily batch-free.

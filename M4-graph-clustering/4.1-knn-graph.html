KNN graph 與 HNSW 加速

KNN Graph & HNSW

在 30 維、100 萬個細胞中找 15 個近鄰要花多久？HNSW 怎麼把 O(n²) 降到 O(n log n)？

Finding 15-NN among 1M cells in 30D. How HNSW reduces O(n²) to O(n log n).

直覺 / Intuition

分群、UMAP、Pseudotime 全部都要 KNN graph。但暴力法（每對細胞算距離）對 100 萬細胞要算 $5 \times 10^{11}$ 對——大概要算到天荒地老。

所以實務上用「近似」演算法：HNSW (Hierarchical Navigable Small World)。

Clustering, UMAP, pseudotime all need KNN. Brute force on 1M cells is $5 \times 10^{11}$ pairs. We use approximate algorithms — HNSW.

核心數學 / Math

KNN graph 定義

KNN graph definition

$$\mathcal{N}_k(i) = \arg\min_{S \subset V, |S|=k} \sum_{j \in S} \|x_i - x_j\|$$

「鄰居」可以是有向（i→j 表示 j 是 i 的近鄰）或無向（mutual KNN）。Seurat 用 mutual + Jaccard 加權，Scanpy 用 UMAP 風格的 fuzzy 加權。

Edges can be directed (j is i's neighbor) or mutual (mNN). Seurat uses mutual + Jaccard; Scanpy uses UMAP-style fuzzy weights.

HNSW 的兩個核心想法two core ideas

  1. Navigable Small World：每個節點有少數「長程連結」+ 多數「短程連結」。從任何點都能 $O(\log n)$ 跳到目標。
  2. Hierarchy：建多層圖。上層稀疏，搜尋從上層開始「粗找」，逐層下沉「細找」。
  1. Navigable Small World: few long edges + many short edges → reach any target in $O(\log n)$.
  2. Hierarchy: multi-layer graph. Sparse top for coarse search, descend for refinement.

搜尋複雜度

Search complexity

$$T_{\text{search}} = O(\log n)$$

建構成本 $O(n \log n)$，記憶體 $O(n \cdot M)$（$M$ = 每節點連結數，典型 16）。

Build: $O(n \log n)$. Memory: $O(n \cdot M)$ ($M$ ≈ 16 connections per node).

Jaccard 邊權重（Seurat）

Jaccard edge weights (Seurat)

$$w_{ij} = \frac{|\mathcal{N}_k(i) \cap \mathcal{N}_k(j)|}{|\mathcal{N}_k(i) \cup \mathcal{N}_k(j)|}$$

兩個細胞「共同鄰居」越多權重越大。比單純距離更穩健。

More shared neighbors → higher weight. More robust than raw distance.

KNN Graph：從 brute-force 到 HNSW

KNN Graph: from brute-force to HNSW

PCA 完成後，scanpy 下一步 sc.pp.neighbors 在你不知不覺中做了一件大事： 為 10,000 個細胞建立近鄰圖。 若用 brute-force 算每對距離，10k cells 要 50,000,000 次浮點運算； 1M cells 直接 5,000,000,000,000 次，跑不完。

這節從 KNN 圖的定義出發，理解為什麼 brute-force 行不通， 然後逐步建構 HNSW（Hierarchical Navigable Small World）—— 一個能在 $O(\log n)$ 時間找近鄰的圖資料結構。 最後解釋 Jaccard 邊權重、scanpy 的 connectivities 矩陣為什麼是 PCA 之後 + clustering 之前的關鍵橋樑。
After PCA, Scanpy's sc.pp.neighbors silently does a heavy job: build a nearest-neighbor graph over your 10k cells. Brute-force: 10k cells → 50M pairwise distances; 1M cells → 5 trillion — infeasible.

We start from KNN graph definition, see why brute-force fails, then build up HNSW (Hierarchical Navigable Small World) — a graph data structure that finds neighbors in $O(\log n)$. Finally, Jaccard edge weights and Scanpy's connectivities matrix — the bridge between PCA and clustering.

🧬 scRNA-seq 視角：KNN 圖是「細胞群落分群」的隱形骨架 🧬 scRNA-seq perspective: KNN graph is the hidden skeleton of cell clustering

📍 在 scRNA-seq 流程中的位置Position in scRNA-seq pipeline

QC → normalize → HVG → scale → PCA (50-D) → KNN graph (sc.pp.neighbors) → Leiden cluster + UMAP + diffusion → all downstream

KNN graph 是 scRNA 流程的「關鍵中繼站」：UMAP、Leiden、diffusion maps、PAGA、RNA velocity 都建在這個 graph 上。它看不見（沒人會 plot 它），但決定了下游所有「鄰居推斷」的對錯。 KNN graph is the critical relay of the scRNA pipeline: UMAP, Leiden, diffusion maps, PAGA, RNA velocity all build on it. It's invisible (nobody plots it), but it decides all downstream "neighbor inference" correctness.

🎯 為什麼 scRNA-seq 必須建 KNN 圖Why scRNA-seq MUST build a KNN graph

  • distance 計算負擔太大，圖是「稀疏」近似distance computation too expensive; graph is a "sparse" approximation： 100k cells × 50-D PCA → 完整距離矩陣 100k×100k = 10G entries（80 GB 記憶體）。KNN 圖只存每 cell 的 15 個鄰居 → 1.5M entries（12 MB）記憶體節省 7000 倍。沒這個近似，atlas-scale 分析根本跑不動。 100k cells × 50-D PCA → full distance matrix 100k×100k = 10G entries (80 GB RAM). KNN graph stores only 15 neighbors per cell → 1.5M entries (12 MB), 7000× memory savings. Without this approximation, atlas-scale analysis is infeasible.
  • 所有 graph-based 分群演算法的輸入Input to all graph-based clustering algorithms： Leiden / Louvain 把 cluster 定義為「圖上密度高的子圖」。KNN graph 的連通性直接決定 cluster 的形狀；同樣資料、k=5 vs k=50 會出不同 cluster 數。 Leiden / Louvain define a cluster as a "densely connected subgraph". KNN graph's connectivity directly determines cluster shape; same data, k=5 vs k=50 gives different cluster counts.
  • UMAP 的高維結構描述High-D structure description for UMAP： UMAP 的「fuzzy simplicial set」就是 KNN graph + Jaccard 邊權重。沒先建 KNN，就沒 UMAP，沒 trajectory，沒 reference mapping。 UMAP's "fuzzy simplicial set" is exactly KNN graph + Jaccard edge weights. No KNN graph → no UMAP, no trajectory, no reference mapping.

§0 故事：5 千萬 vs 5 兆對距離Story: 50M vs 5T distances

PCA 之後你有 10,000 個細胞 × 30 維的 PCA 嵌入。下一步要找「每個細胞最近的 15 個鄰居」（建 KNN graph）。最直接做法：

After PCA, you have 10,000 cells × 30-D embedding. Next: find each cell's 15 nearest neighbors (build KNN graph). Naive way: 

# Brute-force: 算每兩個細胞的距離
for i in range(n):
    for j in range(n):
        d[i,j] = np.linalg.norm(X[i] - X[j])

複雜度 $O(n^2 d)$。對 10k cells × 30 維 = 30 億次運算。實測 ~30 秒。 但 100k cells = 3000 秒（50 分鐘）。1M cells = $O(n^2 d) = 3 \times 10^{13}$ → 不可行。

Complexity $O(n^2 d)$. For 10k cells × 30-D = 3 billion ops, ~30 sec. But 100k = 50 min, 1M = $3 \times 10^{13}$ → infeasible.

§1 KNN 圖的直覺與定義KNN graph intuition & definition

給定資料 $\{x_1, \ldots, x_n\} \in \mathbb{R}^d$ 跟整數 $k$，KNN graph 是個有向圖： 每個點 $x_i$ 連到它「最近的 $k$ 個」鄰居 $\mathcal{N}_k(i)$。

Given data $\{x_1, \ldots, x_n\} \in \mathbb{R}^d$ and integer $k$, the KNN graph is a directed graph: each point $x_i$ links to its $k$ nearest neighbors $\mathcal{N}_k(i)$.

$$\mathcal{N}_k(i) = \arg\min_{S \subset \{1,\ldots,n\} \setminus \{i\}, \; |S|=k} \; \sum_{j \in S} d(x_i, x_j)$$
點 $i$ 的 $k$ 個最近鄰
$k$ nearest neighbors of point $i$

1.1 KNN graph 為何是 scRNA 的「橋」？

1.1 Why KNN is the "bridge" in scRNA

scRNA 流程：PCA (給 PC 嵌入) → KNN graph → UMAP / Leiden。KNN 把連續的 PC 空間轉成離散圖結構， 讓後續的 graph-based clustering / embedding 直接吃「圖」這個更穩定的中介物。

scRNA pipeline: PCA (PC embedding) → KNN graph → UMAP / Leiden. KNN turns continuous PC space into discrete graph structure, giving downstream graph-based methods a more stable intermediate representation.

§4 HNSW 多層導航結構HNSW multi-layer structure

HNSW（Malkov & Yashunin 2018）結合兩個天才想法：

HNSW (Malkov & Yashunin 2018) combines two brilliant ideas:

  1. Navigable Small World：圖上每點有少數「長距離邊」+ 多數「短距離邊」。從任意點出發，用 greedy 搜尋可以 $O(\log n)$ 跳到目標附近。 Navigable Small World: each node has few "long edges" + many "short edges". From anywhere, greedy search reaches target neighborhood in $O(\log n)$.
  2. Hierarchy：建多層圖。上層稀疏（少節點、長邊）做「粗找」；下層密集（全節點、短邊）做「細找」。新節點以幾何分布 $P(\text{level}) = (1-\frac{1}{\ln M})^{\text{level}}$ 隨機決定要存在到第幾層。 Hierarchy: multi-layer graph. Top sparse (few nodes, long edges) for "coarse search"; bottom dense (all nodes, short edges) for "refinement". Each new node's max layer drawn from geometric: $P(\text{level}) = (1-\frac{1}{\ln M})^{\text{level}}$.

4.1 HNSW 搜尋演算法

4.1 HNSW search algorithm

def search_knn(q, k):
    ep = entry_point             # 從最上層的進入點開始
    for level in reversed(range(1, max_level)):
        ep = greedy_search(q, ep, level)   # 在該層找「最近的單一節點」
    return beam_search(q, ep, level=0, k=k)  # 最底層用 beam search 找 top-k

§6 為什麼要先 PCA 再算 KNN？Why PCA before KNN?

直接在 20,000 維基因空間上算 KNN 為何不可行？三個原因：

Why not run KNN directly on 20,000-D gene space? Three reasons:

  1. 計算成本：20k 維的歐氏距離算一次就 20k 次乘加。在 30 維 PC 空間只要 30 次。差 ~700 倍 Compute cost: one 20k-D Euclidean = 20k mul-adds. In 30-D PC space = 30. 700× difference
  2. 維度詛咒：高維下幾乎所有點距離都很相似（距離集中現象），KNN 喪失區分能力 Curse of dimensionality: in high-d, all pairwise distances become similar (distance concentration), KNN loses discriminative power
  3. 雜訊壓縮：PCA 保留前 30-50 PC 已經抓住生物結構，剩下的維度多為技術雜訊；先 PCA 等於先「去噪」 Denoise: PCA's first 30–50 PCs capture biological structure; remaining dimensions are mostly noise. PCA-first = denoising
▸ 距離集中現象的數學 ▸ Math of distance concentration

對 i.i.d. 來自單位球的隨機點 $x_i$，在維度 $d \to \infty$ 時：

For i.i.d. random points $x_i$ on a unit ball, as dim $d \to \infty$:

$$\frac{\max_j \|x_i - x_j\| - \min_j \|x_i - x_j\|}{\min_j \|x_i - x_j\|} \xrightarrow{d \to \infty} 0$$

即「最遠跟最近的距離比」趨近 1，KNN 就喪失意義。先 PCA 把 $d$ 從 20000 降到 30 是關鍵。

"Farthest-to-nearest distance ratio" → 1, KNN becomes meaningless. PCA-first drops $d$ from 20000 to 30 — critical.

§7 Jaccard 邊權重 + connectivities 矩陣Jaccard edges + connectivities

原始 KNN 圖是 0/1 binary（鄰居或不是）。Seurat 用 Jaccard 相似度給邊加權重：

Raw KNN graph is binary (neighbor or not). Seurat reweights edges by Jaccard similarity:

$$w_{ij} = \frac{|\mathcal{N}_k(i) \cap \mathcal{N}_k(j)|}{|\mathcal{N}_k(i) \cup \mathcal{N}_k(j)|}$$
兩細胞共同鄰居越多權重越大
more shared neighbors → higher weight

為什麼用 Jaccard 而不用原始距離？

Why Jaccard instead of raw distance?

直覺Intuition: 兩細胞「共享朋友」說明它們同個社群。雜訊或不穩定的「直接距離」不重要，結構性的同社群才重要。 這也讓邊權重對 PCA 後的尺度變化更穩健。 Two cells "sharing friends" means they belong to the same community. Noisy direct distance matters less; structural co-membership matters more. This also makes edge weights robust to PCA-scale shifts.

7.1 scanpy 的 connectivities 矩陣

7.1 Scanpy's connectivities matrix

scanpy 用 UMAP 的「fuzzy simplicial set」加權，跟 Jaccard 相關但更精細。實質上是一個對稱稀疏矩陣 $C \in \mathbb{R}^{n \times n}$：

Scanpy uses UMAP's "fuzzy simplicial set" weighting — related to Jaccard but finer. Effectively a symmetric sparse matrix $C \in \mathbb{R}^{n \times n}$:

sc.pp.neighbors(adata, n_neighbors=15, n_pcs=30)
adata.obsp["distances"]        # sparse: raw KNN distances
adata.obsp["connectivities"]   # sparse: weighted edges (用於 UMAP / Leiden)

§10 深入：Mutual KNN 為何比 KNN 更穩Deep dive: why mutual KNN beats plain KNN

「k 個最近鄰」這個定義有不對稱性：A 可能說「B 是我的鄰居」，但 B 不認為 A 是它的鄰居（A 距離 B 較遠的鄰居們更近）。 Mutual KNN（MNN）只保留雙向鄰居，得到更可靠的圖。

"k nearest neighbors" is asymmetric: A may say "B is my neighbor", but B doesn't say A back (B's neighbors are closer than A is to B). Mutual KNN (MNN) keeps only bidirectional neighbors — more reliable.

10.1 MNN 的數學

10.1 MNN math

$$E_{\text{MNN}} = \{(i, j) : i \in \mathcal{N}_k(j) \text{ AND } j \in \mathcal{N}_k(i)\}$$
只保「雙方都認可」的邊
Keep only "mutually acknowledged" edges

10.2 在 batch correction 的應用 (Haghverdi 2018)

10.2 Application to batch correction (Haghverdi 2018)

MNN 在跨 batch找鄰居：batch A 細胞 找 batch B 中的鄰居 + batch B 細胞找 batch A 中的鄰居，只保 mutual。這些 mutual neighbors 跨 batch 的 vector 差就是「batch effect 方向」，從而校正。fastMNN, mnnCorrect 是這個原理的工具。

MNN finds cross-batch neighbors: batch A cells find neighbors in batch B + vice versa, keep only mutual. The vector difference between mutual neighbors gives the "batch effect direction" for correction. fastMNN, mnnCorrect implement this.

11.2 Why Leiden on fuzzy beats Leiden on raw

理由Reason: fuzzy weight 讓 Leiden 的 modularity 計算能「分辨強鄰居 vs 弱鄰居」——強連通邊在 modularity 公式裡貢獻大，弱邊小。比 raw 0/1 graph 更能找出真實 cluster boundary，cluster 也更stable across seeds。 Fuzzy weights let Leiden's modularity differentiate "strong vs weak neighbors" — strong edges contribute more in the modularity sum. Better at finding true cluster boundaries than 0/1, more stable across seeds.

12.1 NN-descent 演算法

12.1 NN-descent algorithm

核心想法：「朋友的朋友很可能是朋友」。

Core idea: "friend of a friend is likely a friend".

  1. 給每細胞隨機初始 k 個鄰居 Initialize random k neighbors per cell
  2. 迭代：對細胞 $i$，檢查 $i$ 的鄰居的鄰居—— 看是否比現有鄰居更近 Iterate: for cell $i$, check $i$'s neighbors' neighbors — are they closer than current?
  3. 如果是 → 替換If yes → replace
  4. 直到沒新替換為止（通常 ~ 5 iterations） Until no replacements (typically ~5 iter)

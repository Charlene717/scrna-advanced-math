Louvain & Leiden：把 KNN 圖切成細胞型態

Louvain & Leiden: cutting KNN graph into cell types

有了 KNN graph，下一步是「分群」——把細胞分成 cluster，每個 cluster 對應一個細胞型態。 但「分群」這個詞模糊不清——同一張圖可以切出 5 群、10 群、20 群都「合理」。 我們需要一個量化目標來定義什麼是「好的分群」。

答案是 modularity Q：衡量「群內邊比預期多多少」。 Louvain 演算法用 greedy 兩階段最大化 Q； Leiden 修正 Louvain 會產生斷裂群的 bug。 這節從 modularity 公式出發，用互動模擬看 Louvain 怎麼跑、Leiden 為什麼更穩。
With KNN graph, next step: cluster cells, each cluster = a cell type. But "cluster" is ambiguous — same graph can yield 5, 10, or 20 "reasonable" clusters. We need a quantitative objective for "good clustering".

Answer: modularity Q — "how many more within-cluster edges than expected". Louvain greedily maximizes Q in two phases; Leiden patches Louvain's disconnected community bug. This section derives modularity, simulates Louvain interactively, and shows why Leiden is more reliable.

🧬 scRNA-seq 視角：Leiden 是把「人群」分桌的婚宴企劃 🧬 scRNA-seq perspective: Leiden is the wedding planner who decides who sits at which table

想像你是婚宴企劃，要把 200 位賓客分桌。你有一份「每個人 15 個朋友」的名冊（KNN graph）。聰明的做法不是先決定「分 10 桌」（k-means 的做法）——而是看「哪些人彼此熟、那群就坐一桌」（Leiden 的做法）。Leiden 用一個叫 modularity 的分數衡量分桌好不好：「同桌的人比預期更熟」分數就高。它自己決定該分幾桌，不用你預先告訴它。 Imagine you're a wedding planner seating 200 guests. You have a "15 best friends per guest" register (KNN graph). The smart move isn't to declare "10 tables" upfront (that's k-means) — it's to ask "which guests know each other well, put them at one table" (that's Leiden). Leiden scores seating arrangements with modularity: "guests at the same table are friendlier than expected" → high score. It decides table count itself, no need to pre-specify.

為什麼 scRNA 一定要用 Leiden 而不是老派的 k-means？因為 (1) 你一開始不知道有幾種細胞型（pDC 可能 0.5%、monocyte 可能 30%，差 60 倍）；(2) cell type 在 PCA 空間是奇形怪狀的曲面，k-means 的「球形假設」整個崩盤；(3) Leiden 還修了它哥哥 Louvain 的一個重大 bug——Louvain 會把「兩桌不認識的人」標成同一桌（圖上不連通的 cluster），Leiden 用三階段流程保證每桌的人都互相認識（Traag 2019）。所以 scanpy 自 1.4.4 起內建 sc.tl.leiden，Heumos 2023 best practices 也明白推薦改用 Leiden 取代 Louvain。 Why must scRNA use Leiden instead of old-school k-means? Because (1) you don't know the cell-type count upfront (pDC might be 0.5%, monocyte 30% — 60× imbalance); (2) cell types form weirdly curved surfaces in PCA space, totally breaking k-means' spherical assumption; (3) Leiden patches a major bug in its older brother Louvain — Louvain sometimes labels "two tables of strangers" as one table (graph-disconnected cluster); Leiden's 3-phase pipeline guarantees everyone at the same table actually knows each other (Traag 2019). Scanpy ships sc.tl.leiden since v1.4.4, and Heumos 2023's best-practices review explicitly recommends Leiden over Louvain.

Pick Leiden (not Louvain) + reasonable resolution + cross-seed stability — that's the final gatekeeper turning scRNA-seq from "pretty plot" to "trustworthy conclusion".

§0 故事：什麼叫「好的分群」？Story: what is "good" clustering?

你拿到 KNN graph：10,000 個細胞 + 邊。同樣這張圖，你可以切成：

You have a KNN graph: 10,000 cells + edges. Same graph, multiple partitions:

  • 1 群：所有細胞在一起 — 沒分群
  • 1 group: all cells together — no partition
  • 10,000 群：每細胞自己一群 — 等於沒分
  • 10,000 groups: each cell alone — equivalent to no partition
  • 2 群、5 群、15 群...都「看起來」合理
  • 2, 5, 15 groups... all "look" reasonable

怎麼挑「正確」的分群？我們需要一個客觀分數。Newman & Girvan (2004) 提出 modularity Q：

How to pick the "right" partition? We need an objective score. Newman & Girvan (2004) proposed modularity Q:

直覺定義Intuitive definition: Q = (群內邊比例) − (如果是隨機圖會有的群內邊比例)。Q 越大，分群「越像有結構」。 Q = (within-cluster edge fraction) − (random-graph baseline). Higher Q → more "structured" partition.

§1 Modularity Q 的數學Modularity Q math

$$Q = \frac{1}{2m} \sum_{i,j} \left[ A_{ij} - \frac{k_i k_j}{2m} \right] \delta(c_i, c_j)$$
$A_{ij}$ = 鄰接矩陣、$k_i$ = 點 $i$ 的度、$m$ = 總邊數、$\delta(c_i, c_j)$ = 1 若 $i, j$ 同 cluster 否則 0
$A_{ij}$ = adjacency, $k_i$ = degree of $i$, $m$ = # edges, $\delta(c_i, c_j)$ = 1 if same cluster else 0

1.1 拆解每一項的意義

1.1 Decompose each term

項Term 意義Meaning
$A_{ij}$$A_{ij}$ 實際 $i, j$ 之間是否有邊 actual edge between $i, j$
$\frac{k_i k_j}{2m}$$\frac{k_i k_j}{2m}$ 隨機圖（保留 degree）期望的邊數 expected edges in random graph (degree-preserving)
$A_{ij} - \frac{k_i k_j}{2m}$$A_{ij} - \frac{k_i k_j}{2m}$ 「比預期多的邊」 "excess edges over expectation"
$\delta(c_i, c_j)$$\delta(c_i, c_j)$ 只算「同 cluster」的對 only count "same cluster" pairs
$\frac{1}{2m} \sum$$\frac{1}{2m} \sum$ 標準化到 [-1, 1] 之間 normalize to [-1, 1]

1.2 Q range and interpretation

§3 Louvain 兩階段演算法Louvain two-phase algorithm

Blondel et al. (2008) 的 Louvain 用 greedy 找局部最佳 Q：

Blondel et al. (2008) Louvain greedily finds local-optimal Q:

3.1 Phase 1：節點重指派

3.1 Phase 1: node reassignment

  1. 每個節點各自一群Each node starts in its own community
  2. 隨機順序走訪每個節點 $i$Visit each node $i$ in random order
  3. 試把 $i$ 移到鄰居 $j$ 所屬的 community，算 ΔQTry moving $i$ to each neighbor $j$'s community, compute ΔQ
  4. 把 $i$ 移到讓 ΔQ 最大的群（若沒提升就留原處）Move $i$ to whichever maximizes ΔQ (or stay if no improvement)
  5. 重複直到沒節點要移動Repeat until no node moves

3.2 Phase 2：圖收縮

3.2 Phase 2: graph contraction

  1. 把每個 community 視為「超節點」，得到新圖Each community becomes a "super-node", forming new graph
  2. 超節點之間的邊權 = 原圖兩 community 之間所有邊權加總Super-edge weight = sum of all original edges between two communities
  3. 用新圖回到 Phase 1，直到 Q 不再改善Run Phase 1 on new graph, until Q stops improving

3.3 ΔQ 的閉式公式

3.3 ΔQ closed form

$$\Delta Q = \left[\frac{\Sigma_{\text{in}} + 2 k_{i,\text{in}}}{2m} - \left(\frac{\Sigma_{\text{tot}} + k_i}{2m}\right)^2\right] - \left[\frac{\Sigma_{\text{in}}}{2m} - \left(\frac{\Sigma_{\text{tot}}}{2m}\right)^2 - \left(\frac{k_i}{2m}\right)^2\right]$$
$\Sigma_{\text{in}}$ = community 內邊權總和；$\Sigma_{\text{tot}}$ = 該 community 所有節點度總和；$k_{i,\text{in}}$ = $i$ 連到該 community 的邊權
$\Sigma_{\text{in}}$ = sum of community's internal edge weights; $\Sigma_{\text{tot}}$ = sum of community's node degrees; $k_{i,\text{in}}$ = $i$'s edges into community

關鍵：ΔQ 可以局部計算（只看 $i$ 跟目標 community），所以每次重指派 $O(k_i)$，整體 $O(m)$，能做百萬節點。

Key: ΔQ is local (only $i$ and target community), so each reassignment is $O(k_i)$, total $O(m)$ — scales to millions.

§5 Louvain 的斷裂群 bugLouvain's disconnected community bug

Louvain 有個嚴重 bug（Traag et al. 2019 才指出）： Phase 1 在重指派節點時，可能把「中介節點」搬走， 讓原本連通的 community 變成實際上斷裂的兩半，但 Louvain 不檢查、繼續當成一個 community。

Louvain has a serious bug (only identified by Traag et al. 2019): Phase 1's reassignments can remove a bridge node, leaving the original community physically disconnected, but Louvain doesn't check — it continues treating them as one community.

5.1 具體例子

5.1 Concrete example

上圖：原本 community A = {1, 2, 3, 4, 5}，其中 3 是 1-2 跟 4-5 的橋。 Louvain 把 3 重指派給 community B（紫色）後， A 就剩 {1, 2} 和 {4, 5} 兩塊互不連通，但 Louvain 仍當成同一群。

Above: original A = {1, 2, 3, 4, 5}, where 3 bridges {1,2} and {4,5}. Louvain moves 3 to B (purple), leaving A = {1,2} ⊔ {4,5} — physically disconnected, but treated as one cluster.

後果Consequence: scRNA 上這個 bug 會讓你的「T 細胞 cluster」其實是兩個不相連的子群被合在一起——影響下游 DE 分析、軌跡推斷。2019 之後不該再用 Louvain。 In scRNA, this bug means your "T cell cluster" may actually be two disconnected subgroups — corrupting downstream DE, trajectory inference. Don't use Louvain post-2019.

6.1 Leiden 提供的數學保證

6.1 Leiden's guarantees

  1. connectivity：每個 community 都是連通的（Louvain 不保證） Connectivity: every community is connected (Louvain doesn't guarantee)
  2. γ-separation：每對 community 之間滿足「分開比合併好」的條件 γ-separation: every community pair satisfies "splitting is better than merging"
  3. well-connectedness：每個 community 內部沒有「明顯該分開的子群」 Well-connectedness: no internal "obvious sub-partition" within any community

6.2 速度跟結果

6.2 Speed and quality

實測Empirical: Leiden 在大圖上其實比 Louvain 快（refinement 給 Phase 3 更好起點），且 Q 更高。 scanpy / Seurat 最新版本預設都用 Leiden。 On large graphs, Leiden is actually faster than Louvain (refinement gives Phase 3 a better start) and higher Q. Recent Scanpy / Seurat versions default to Leiden.

§7 Resolution γ 與群數量Resolution γ vs # clusters

原始 modularity 有個著名缺陷：resolution limit——對大圖找不到小 community。 解法是加上 resolution 參數 $\gamma$：

Vanilla modularity has a famous flaw: resolution limit — small communities go undetected in large graphs. Fix: add resolution parameter $\gamma$:

$$Q_\gamma = \frac{1}{2m} \sum_{i,j} \left[ A_{ij} - \gamma \frac{k_i k_j}{2m} \right] \delta(c_i, c_j)$$

γ 越大 → 群越多越小；γ 越小 → 群越少越大。scanpy 預設 $\gamma = 1$。

Larger γ → more, smaller clusters; smaller γ → fewer, bigger. Scanpy default $\gamma = 1$.

§10 深入：Constant Potts Model (CPM) — Leiden 的另一個 quality functionDeep dive: Constant Potts Model (CPM) — Leiden's alternative quality function

Leiden 不只支援 modularity，還支援 CPM（Traag, Van Dooren & Nesterov 2011）。 CPM 避免 modularity 的 resolution limit，對「同樣大小的小 cluster 都能找到」特別好。

Leiden supports not only modularity but also CPM (Traag, Van Dooren & Nesterov 2011). CPM avoids modularity's resolution limit, especially good at finding "small clusters of similar size".

10.1 CPM 公式

10.1 CPM formula

$$\mathcal{H}_{\text{CPM}} = \sum_c \left[ e_c - \gamma \binom{n_c}{2} \right]$$
$e_c$ = cluster $c$ 內邊數、$n_c$ = cluster size、$\gamma$ = resolution（密度門檻）
$e_c$ = within-cluster edges, $n_c$ = cluster size, $\gamma$ = resolution (density threshold)

§11 Consensus clustering：穩定 cluster 的最佳實踐Consensus clustering: best practice for stable clusters

Leiden 是 stochastic 的（受 seed 影響）。同一個 γ 跑 100 次可能得到略不同 cluster。 Consensus clustering（Monti 2003）跑多次後取「共同」結果，得更穩定 cluster。

Leiden is stochastic (seed-dependent). Same γ run 100 times may give slightly different clusters. Consensus clustering (Monti 2003) takes "shared" results across many runs for stability.

11.1 演算法

11.1 Algorithm

  1. 跑 Leiden 100 次（不同 seed） Run Leiden 100× (different seeds)
  2. 對每對 cell (i, j) 算「他們被分到同 cluster 的次數比例」 For each cell pair (i, j), compute "fraction of runs they're in same cluster"
  3. 得 consensus matrix M (n × n) Get consensus matrix M (n × n)
  4. 對 M 做 hierarchical clustering 得最終 cluster Hierarchical cluster on M → final clusters

§12 Hierarchical Leiden：找 nested cell typesHierarchical Leiden: nested cell types

細胞型態是階層的：T cell → CD4 T → CD4 naive / memory；B cell → naive B / memory B / plasma。 單一 γ 抓不到所有層級。Hierarchical Leiden 解這個。

Cell types are hierarchical: T cell → CD4 T → CD4 naive / memory; B cell → naive / memory / plasma B. Single γ misses some levels. Hierarchical Leiden solves this.

12.1 兩階段方法

12.1 Two-stage approach

# Stage 1: coarse clustering
sc.tl.leiden(adata, resolution=0.3, key_added="leiden_coarse")
# → 7 clusters: T / Mono / B / NK / DC / Plasma / Mega

# Stage 2: 對每個 coarse cluster 內部 sub-cluster
for cluster in adata.obs["leiden_coarse"].unique():
    mask = adata.obs["leiden_coarse"] == cluster
    sub_adata = adata[mask].copy()
    sc.pp.neighbors(sub_adata, n_neighbors=10)
    sc.tl.leiden(sub_adata, resolution=1.0, key_added="sub")
    adata.obs.loc[mask, "leiden_fine"] = (
        cluster + "_" + sub_adata.obs["sub"].astype(str)
    )
# → "T_0", "T_1", "T_2" (CD4/CD8/...) etc.

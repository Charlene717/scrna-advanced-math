Scaling 的高斯假設

Scaling & the Gaussian Assumption

PCA 為什麼需要 z-score？對計數資料 scale 會破壞什麼？SCTransform 為什麼可以省略 scale？

Why PCA needs z-score. What scaling destroys in count data. Why SCTransform can skip scaling.

直覺 / Intuition

PCA 不會「自動」處理單位差異

PCA does not handle scale differences

PCA 找變異最大的方向。若 Gene A 平均 1000、Gene B 平均 10，PC1 必定被 Gene A 主宰——因為它的數值絕對值大。但「數值大」≠「資訊多」。

解法：讓每個基因有相同的「方差預算」，這就是 z-score：

PCA finds maximum-variance directions. If Gene A averages 1000 and Gene B averages 10, PC1 will be dominated by Gene A — but "large value" ≠ "informative". Solution: give every gene the same variance budget.

核心數學 / Math
$$z_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j}, \quad \mu_j = \frac{1}{n}\sum_i x_{ij}, \quad \sigma_j = \sqrt{\frac{1}{n-1}\sum_i (x_{ij}-\mu_j)^2}$$

每個基因（欄）變成 mean=0、var=1。等於：「每個維度被『重新校準』成同樣的尺度」。

Each gene (column) → mean=0, var=1. Every dimension is rescaled to identical magnitude.

⚠️ Scale 是雙刃劍⚠️ Scaling is double-edged

放大噪音：低表現基因的 σ 很小，scale 後反而把「微小的隨機波動」放大。
破壞計數本質：對 0/1/2 這種離散計數做 z-score 之後，0 變成負值——「沒表現」變成「比平均低」，意義轉變。

Amplifies noise: σ of low-expression genes is tiny, so random fluctuations get magnified.
Destroys count nature: z-scoring 0/1/2 discrete counts turns "not expressed" into "below average", changing meaning.

SCTransform 為什麼可以省略 scale？

Why can SCTransform skip scaling?

SCTransform 的 Pearson residuals 已經是 $(x - \hat\mu) / \sqrt{\hat\mu + \hat\mu^2/\hat\theta}$—— 本質上已經是 z-score（分子減均值、分母除標準差），只是用 NB 模型算的而非樣本估計。所以後續可直接 PCA、不需另外 scale。

SCTransform's Pearson residuals are already $(x - \hat\mu) / \sqrt{\hat\mu + \hat\mu^2/\hat\theta}$ — essentially z-scores computed from NB model, not sample statistics. Can go directly to PCA without re-scaling.

回歸出 unwanted variation

Regressing out unwanted variation

Seurat 的 ScaleData(vars.to.regress=...) 在 scale 同時做線性回歸：

$$z_{ij} = \text{residual of } x_{ij} \sim \beta_0 + \beta_1 \cdot \text{nCount}_i + \beta_2 \cdot \text{MT\%}_i + \ldots$$

用線性模型「扣掉」這些混淆變數的影響。注意：這假設它們的影響是線性的——對 nCount 不一定成立。

Linear model removes confounder effects. Assumes linearity, which may not hold for nCount.

程式碼 / Code 
sc.pp.scale(adata, max_value=10)    # clip extreme values

# 回歸 out 混淆變數
sc.pp.regress_out(adata, ["total_counts", "pct_counts_mt"])
sc.pp.scale(adata, max_value=10)

pbmc <- ScaleData(pbmc, vars.to.regress = c("nCount_RNA", "percent.mt"))

# SCTransform 已內建，這步可省略
pbmc <- SCTransform(pbmc, vars.to.regress = "percent.mt")
